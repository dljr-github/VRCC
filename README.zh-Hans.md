# VRCC

本文档还提供 [English](README.md)、[日本語](README.ja.md) 和 [한국어](README.ko.md) 版本。

对着麦克风说话，你说的话就会以实时字幕的形式出现在 VRChat 聊天框里，下面还会附上最多三种语言的翻译。一切都在你自己的 Windows 10 或 11 电脑上运行。没有云服务，也不需要 API 密钥。

```
You say:   "Hello, how are you today?"
Chatbox:   Hello, how are you today?
           こんにちは 今日はどうですか?
```

VRCC 追求即插即用。运行它，首次启动向导就会评估你的电脑，替你挑好模型并设定性能模式；每一条推荐都来自实测的基准测试，而不是凭猜测。各种细调选项仍然留在“设置”里，但你应该用不到它们。

## 让 VRCC 跑起来

大约需要五分钟，另外加上一次性的模型下载。不用安装 Python，也不用去找什么 API 密钥；一切都在 Windows 10 或 11 上本地运行。

<a id="download"></a>

1. 打开 Releases 页面。可以直接运行的程序不在你最先看到的仓库页面上，它在 [Releases](https://github.com/dljr-github/VRCC/releases/latest) 里。那个链接会直接带你到最新的一个。你会看到版本号、发布说明，以及页面底部一个标题为 **Assets** 的列表。文件就在那里面。

   Assets 下面的最后两项，“Source code (zip)”和“Source code (tar.gz)”，是 VRCC 自己的源代码，不是程序本身。这两个都跳过。你要二选一的是 `VRCC-cuda-windows-x64` 和 `VRCC-windows-x64`，每个名字后面都跟着版本号。

2. 挑一个适合你电脑的 zip。`VRCC-cuda-windows-x64` 是 CUDA 版本，适合显存 8 GB 或以上、驱动 570 或更新的 NVIDIA 显卡。字幕在显卡上算出来，几乎立刻就会出现。`VRCC-windows-x64` 是 CPU 版本，下载体积小得多，显存不到 8 GB 的 NVIDIA 显卡、AMD 或 Intel 显卡，以及根本没有显卡的电脑，都该拿这个。字幕内容完全一样，只是慢上一点点，而且默认模型的大小就是照着 CPU 跟得上来选的。

   想知道自己是什么配置，按 Ctrl+Shift+Esc 打开任务管理器（Task Manager），打开**性能**（Performance）选项卡，点击 **GPU**。显卡的名称、专用内存和驱动版本都在那一页上。如果你不想去看，就拿 CUDA 版的 zip。它下载体积更大，但在找不到能用的显卡时，会自己改用处理器运行。

   目前 GPU 加速只支持 NVIDIA 显卡，因为这边没有 AMD 硬件可以测试。

3. 先解除 zip 的锁定，再解压。右键点击你下载的文件，在菜单最下面选择**属性**（Properties）。如果“常规”（General）选项卡靠近底部的地方有一个**解除锁定**（Unblock）复选框，勾上它，然后点“确定”（OK）。Windows 会给来自互联网的文件打上标记，在这里把标记清掉，还能省掉下一步里的那个警告。

   然后再次右键点击这个 zip，选择**全部解压缩**（Extract All）。资源管理器会把 zip 显示得像一个文件夹，但从里面直接启动程序，等于只把压缩包中间的一个文件交给 Windows，它是跑不起来的。解压到“文档”（Documents）之类的地方，你会得到一个 VRCC 文件夹，里面有 `VRCC.exe`。把这个文件夹整个保留在一起，想放哪里都行。没有任何东西需要安装。

4. 运行 `VRCC.exe`。在刚解压出来的文件夹里双击它。Windows 可能会弹出一个蓝色窗口，标题是“Windows 已保护你的电脑”（Windows protected your PC）。点击**更多信息**（More info），也就是提示文字下面那个小链接，再点击出现的**仍要运行**（Run anyway）按钮。VRCC 没有代码签名，所以 Windows 对这种还不常见的程序就会这样提示。对于你从上面 Releases 页面拿到的文件，这个提示值得点过去，但这并不是说在别的地方也可以随手点过去。如果你刚才勾了解除锁定，它可能根本不会出现。

5. 让首次启动向导下载模型。第一次启动 VRCC 时，向导会检查你的电脑，替你选好一个语音转文字模型和一个翻译模型（大约要下载 1 到 3 GB），然后开始下载。在下载开始前，你可以改运行设备或模型。这一步只会发生一次。[首次启动](#first-run)里有它挑了什么、为什么这么挑的表格。

6. 在 VRChat 里启用 OSC。打开 **Action menu → Options → OSC → Enabled**。VRCC 通过 OSC 把字幕发给 VRChat（默认地址 `127.0.0.1:9000`）；不开这个，字幕就到不了聊天框。

7. 选择麦克风和语言。在 VRCC 里选好你的**麦克风**、你的**源语言**（你说的那种语言），以及最多**三种要翻译成的目标语言**。

8. 开始说话。你说的话会以实时字幕出现在 VRChat 聊天框里，下面跟着翻译。你也可以在窗口底部的输入框里打字，用同样的方式把文本发出去。

之后可以打开**设置**来更改界面语言、更换模型，或者在“速度”和“质量”模式之间切换。[使用方法](#usage)讲的是 VRCC 日常的其他功能，如果字幕一直没出现，就从[疑难解答](#troubleshooting)开始查。从源码构建是给想参与开发的人准备的（见 [DEVELOPING.md](DEVELOPING.md)）。

<a id="what-runs-on-your-machine"></a>

## 在你电脑上运行的东西

你的声音不会离开你的电脑。VRCC 背后没有云服务，也没有要粘贴的 API 密钥。

语音识别走的是 [faster-whisper](https://github.com/SYSTRAN/faster-whisper)，欧洲语言也可以用 NVIDIA 的 [Parakeet TDT 0.6B v3](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3)（以 ONNX 导出的形式，通过 [onnx-asr](https://github.com/istupakov/onnx-asr) 运行），中文、日语、韩语和英语还有 [SenseVoice-Small](https://huggingface.co/FunAudioLLM/SenseVoiceSmall) 可选，它能用，但不推荐。机器翻译走的是 [CTranslate2](https://github.com/OpenNMT/CTranslate2)，配合 NLLB、M2M100 和 MADLAD 模型。向导会替你从这些里面挑，[挑选模型](#picking-a-model)里有支撑这些选择的实测数据。

<a id="first-run"></a>

## 首次启动

如果配置好的模型还没下载，就会打开首次启动向导，它会按你的硬件和你所说的语言（取自 Windows 的显示语言）挑选模型，然后下载：

| 你的电脑 | 语音转文字 | 翻译 | 下载量 |
| -------- | ---------- | ---- | ------ |
| 显存 16 GB 以上的 NVIDIA 显卡 | `large-v3-turbo` | `nllb-1.3B-int8` | 约 3 GB |
| 显存 11 GB 到 16 GB 的 NVIDIA 显卡 | `large-v3-turbo` | `nllb-600M-int8` | 约 2.3 GB |
| 没有显卡，或显存不到 11 GB 的 NVIDIA 显卡，且是 Parakeet 支持的语言 | `parakeet-tdt-0.6b-v3` | `nllb-600M-int8` | 约 1.3 GB |
| 没有显卡，或显存不到 11 GB 的 NVIDIA 显卡，其他语言 | whisper `small` | `nllb-600M-int8` | 约 1.1 GB |

VRChat 本身就要占用显卡的大量显存。VRCC 给它预留 8 GB，再按翻译模型算完之后显卡还剩下多少，来决定语音模型的大小，所以 `large-v3-turbo` 需要的是大约 11 GB 而不是 8 GB：低于这个数，留给 VRChat 一起运行的空间就太少了。

日语、韩语和中文用的模型和其他语言一样。Parakeet 不支持它们，所以没有显卡、或者 NVIDIA 显卡显存不到 11 GB 的电脑，会拿 whisper `small` 而不是 Parakeet。`sense-voice-small` 在“模型”窗口里仍然可选，体积也小得多（240 MB），但在测试中，faster-whisper 对真实 VRChat 语音的转写更准确，所以它已经不再是推荐项。

向导会显示它挑了什么，并让你在下载前更改运行设备。

![首次启动向导为 NVIDIA 显卡推荐模型](assets/images/firstrun.png)

其他可选项从 whisper `tiny`（约 75 MB）一直到 `large-v3`（约 3 GB），另外还有 NVIDIA 的 `parakeet-tdt-0.6b-v3`（约 690 MB，非常准确也非常快），但它只支持英语和另外 24 种欧洲语言（不支持日语、韩语、中文）。翻译模型则从 `m2m100-418M-int8`（约 480 MB）到 `madlad400-3b`（约 3.5 GB）。按实测的字幕质量，NLLB 在推荐里排在最前面；M2M100 系列是许可证更宽松的替代选择（见[模型许可证](#model-licenses)）。模型之后可以通过**模型**对话框添加或删除。实测的准确度和速度见下面的[挑选模型](#picking-a-model)。

VRCC 准备好运行之后，主窗口旁边会打开一个设置步骤面板，上面的几行分别是：开启字幕、语音模型加载完成、你的声音传到了 VRCC、在网络上找到了 VRChat，以及一条字幕通过 OSC 发了出去，另外还有一行可选的、关于从扬声器捕捉到的声音，它从不影响其他几行。VRChat 那一行只能证明它的 OSC 服务通过 mDNS 做了广播，并不能证明有什么东西真的到了游戏里，所以在屏蔽 mDNS 的网络上，这一行可能一直没打勾，而 VRChat 其实运行得好好的，只要这种情况还在，面板每次启动都会继续打开。字幕那一行的证据方向正相反。它证明的是字幕已经发出，而不是 VRChat 收到了，因为 OSC 从来不会确认消息有没有送达；一旦关掉了向 VRChat 发送，这一行就不再算在面板要求的项目里。等面板仍然要求的每一行都通过了，以后启动就不会再打开它。在那之前把它关掉，只对当次会话有效，下次启动它还会回来。面板上还有一个“不再显示”按钮，不管要求的行是否都已经通过，都能用它把面板永久关掉。不管用哪种方式关掉，在“设置”的“简易”页面里，随时都可以把它调回来。

<a id="usage"></a>

## 使用方法

1. 启动 VRChat 并启用 OSC：**Action menu → Options → OSC → Enabled**。
2. 启动 VRCC。选好你的麦克风、源语言，以及最多三种目标语言。
3. 说话。你的麦克风声音会先被清掉持续的背景噪音（默认开启），然后自动切分成一句一句（Silero VAD），转写、翻译，再发到聊天框，发送速度受到限制，以保持在 VRChat 聊天框的频率上限之内，这样一直说话也不会触发游戏里的刷屏禁言。想把它调低或关掉，去**设置 → 语音识别 → 降低背景噪音**。
4. **读懂别人说的话：** 点击主窗口的**听其他人**（Hear others），就能把扬声器里传出来的人声转写并翻译，这样对方说的语言你看不懂，也能跟上。在**设置 → 简易 → 其他人说的话**（What other people say）里选择监听来源和显示语言。有两点要知道。它捕捉的是整个输出设备，而不是 VRChat 的语音通道，因为 Windows 没有提供按应用抓取语音的办法，所以游戏和世界的声音也会被转写。还有，它只显示在 VRCC 窗口里：别人说的话永远不会被发到聊天框，因为房间里的人已经听到了，再转发一遍等于用你的名义把他们的话重新发布一次。没有显卡时，它会和你自己的字幕共用一个语音模型，两边都会变慢。
5. **打字发送：** 主窗口底部的文本框会把你打的字，通过同样的“翻译 → 聊天框”路径发出去（不想开口说话的时候很好用）。
6. **静音同步：** 开启后，在 VRChat 里把自己静音，VRCC 就会完全停止收听（可以配置成忽略静音或者反过来）。静音期间说的话完全不会被捕捉，所以说到一半解除静音，只会为解除之后说的内容生成字幕。这用到了 VRChat 的 OSCQuery 发现机制，**只有 VRChat 和 VRCC 在同一台电脑上运行时**（localhost）才有效；字幕功能本身不受影响。

![主窗口正在生成字幕，带日语和西班牙语翻译](assets/images/main-window.png)

<a id="interface-language"></a>

### 界面语言

界面默认跟随 Windows 的显示语言，支持 18 种语言（English、日本語、한국어、简体中文、繁體中文、Español、Français、Deutsch、Italiano、Português (Brasil)、Русский、Українська、Polski、Nederlands、Türkçe、Bahasa Indonesia、Tiếng Việt、ไทย）。想换一种，去**设置 → 简易 → 语言**；关闭设置窗口后立刻生效。这只影响 VRCC 自己的界面；字幕语言是在主窗口里选的。

<a id="performance-modes"></a>

### 性能模式

**设置 → 简易 → 模式**在两套预设之间切换：

- **速度**（默认）：贪心解码（beam 1），静音 600 ms 之后就把一条字幕定稿。字幕出现得最快。
- **质量**：beam 5，等待 800 ms。措辞明显更好，每条字幕大约慢 200 ms。

模式只影响字幕。翻译有自己的搜索宽度，在**设置 → 翻译 → 高级（精细调节）**里，因为这些预设背后的测量只涵盖语音识别，并不涉及翻译。

切换模式会重写“高级”页面上的停顿时间，以及“语音识别”页面上的“搜索宽度”。如果这里面有你自己手动设过的，VRCC 会逐项列出，先问你一声；只是在两种模式之间来回切换做对比时不会提示，因为那些值来自预设，不是你设的。

Parakeet 和 SenseVoice 始终以完整精度解码，所以只要其中之一是当前的语音模型，“模式”这个控件就是灰的。各个单独的调节项（VAD 时间、beam 大小、质量门限等等）在**设置 → 高级**里。

<a id="picking-a-model"></a>

## 挑选模型

本节里的每一个数字都来自 `tools/bench_stt.py`：100 条 [LibriSpeech](https://www.openslr.org/12/) test-clean 语音，走应用实际使用的同一条引擎路径，在同一台电脑上跑出来（Windows 11、Ryzen 9 9950X3D、RTX 5090、驱动 610.62）。WER 是英语朗读语音的词错误率；延迟是转写一条语音所用时间的中位数。准确度数字和相对的速度倍数可以套到别的电脑上，绝对延迟不行。在更慢的 CPU 上，这里每一个 CPU 时间大致都会按同样的倍数拉长。完整的表格和方法说明在 [DEVELOPING.md](DEVELOPING.md#speech-to-text-benchmarks) 里，[benchmarks/RESULTS.md](benchmarks/RESULTS.md) 收集了其他硬件上的数字。

在 NVIDIA 显卡上，保持默认的 `large-v3-turbo`。它的 WER 和 `large-v3` 一样是 1.7%，速度却快了约 3.5 倍，而且它支持所有语言。

在 CPU 上，取决于你说什么语言：

- 25 种欧洲语言之一：用 `parakeet-tdt-0.6b-v3`。它以 0.13 s 达到 2.3%，在准确度*和*延迟上都赢过默认的 `small`（3.7%，0.74 s），而且不是小赢。在这一组语言里，它还能自己判断说的是哪一种。
- 日语、韩语、中文，或者这一组之外的任何语言：继续用 `small`。所有能赢过它的 whisper 模型，在 CPU 上每条字幕都要花上好几秒。

Parakeet 在 CPU 上比在 GPU 上还快（0.13 s 对 0.21 s），因为它的 int8 ONNX 计算图不适合 CUDA。所以对它来说 CPU 版本就够了，而且如果你在同一台电脑上玩 VRChat，这样还能把整块显卡留给游戏。设备保持在“自动”时，VRCC 会替你这么做。

在这些测试里，distil 系列模型在 GPU 上输给 `large-v3-turbo`，在 CPU 上输给 Parakeet 和 `small`，所以没什么理由选它们。

首次启动向导会按你的硬件和你所说的语言来挑，后者取自你的 Windows 显示语言。在 CPU 上这意味着：你说的语言 Parakeet 支持就用 Parakeet，不支持就用 `small`。把所说语言设成“自动”，它就会一直用 whisper 系列：事先不知道是哪种语言，就没法指望一个只覆盖欧洲语言的模型能应付。

<a id="where-things-are-stored"></a>

## 文件存放位置

| 内容 | 默认位置 |
| ---- | -------- |
| 配置 | `%LOCALAPPDATA%\VRCC\VRCC\config.json` |
| 模型 | `%LOCALAPPDATA%\VRCC\VRCC\models\` |
| 日志 | `%LOCALAPPDATA%\VRCC\VRCC\logs\vrcc-<date>-<time>.log` |

每次运行都会写一个自己的日志文件，记录完整的调试细节，并保留最新的五个。报告问题时，请附上那个文件夹里最新的文件。

加上 `--portable` 运行，配置、模型和日志就改为放在程序自己的目录里（放在 U 盘上或者做独立安装时很方便）。

<a id="updating"></a>

## 更新

VRCC 启动时会看看有没有更新的版本，找到了就弹出一条提示。提示里有一个按钮，点了会在浏览器里打开发布页面。它不会替你下载或替换任何东西，所以更新的步骤和第一次一样：拿到新的 zip，解除锁定，解压，然后从新文件夹里运行 `VRCC.exe`。

你的设置和下载好的模型并不在程序文件夹里（见上面的表格），所以它们会自己留下来。模型不会再下载一遍，首次启动向导也不会再出现。你可以先留着旧文件夹，等用着满意了再删掉。

如果你不想被通知，打开**设置**，进入**高级**（Advanced / Power users）页面，取消勾选**有新版本时通知我**。

便携安装则正好相反。在 `--portable` 下，配置、模型和日志都放在程序自己的文件夹里，所以把那个文件夹换掉，就等于把它们扔了。先把 `config.json` 和 `models` 文件夹复制到新的文件夹里，或者把新版本直接解压覆盖到旧的上面。

<a id="model-licenses"></a>

## 模型许可证

本仓库里的**代码**和它下载的**模型**是分开的；请确认某个模型的许可证适合你的用途：

- **NLLB** 模型（默认的 `nllb-600M-int8`，另有 1.3B 和 3.3B）：**CC-BY-NC-4.0**，*仅限非商业用途*。它们是推荐的模型，所以如果你把 VRCC 用于商业用途（付费或有赞助的直播，或者在工作中使用），请改在**模型**窗口里选一个 M2M100 模型。
- **M2M100** 模型（`m2m100-418M-int8`，另有 1.2B）：**MIT**，因此没有这类限制。在一次针对 60 条 VRChat 风格语句、翻译成日语、中文和韩语的盲测对比中，它们不如 NLLB 600M 准确，这就是换来宽松许可证的代价。
- **MADLAD-400**（`madlad400-3b`）：**Apache-2.0**。
- whisper 模型：**MIT**（OpenAI 权重，SYSTRAN CT2 转换版）。
- **Parakeet**（`parakeet-tdt-0.6b-v3`）：**CC-BY-4.0**（NVIDIA 权重，istupakov 的 ONNX 导出版）。

<a id="troubleshooting"></a>

## 疑难解答

- **“未检测到 GPU”／一切都在 CPU 上运行**：确认你运行的是 CUDA 版本（`VRCC-cuda-windows-x64` 那个 zip，或者用 `pip install -e .[cuda]` 从源码安装），并且 NVIDIA 驱动 ≥ 570。目前 GPU 加速只支持 NVIDIA（没有 AMD 硬件可以测试）。除此之外，只用 CPU 运行是正常的：字幕内容完全一样，只是慢上一点点；默认模型的大小就是照着 CPU 跟得上来选的。
- **显卡显存不够用**：引擎会在本次会话里自动退回到 CPU（int8）运行（字幕一样，延迟更高）；想留在显卡上，就挑一个更小的模型。
- **VRChat 里不显示字幕**：在 VRChat 里启用 OSC（Action menu → Options → OSC），并检查 VRCC 设置里的 OSC 地址和 VRChat 监听的地址是否一致（默认 `127.0.0.1:9000`）。如果你还用了别的 OSC 工具（比如 OSCRepeater 这类转发工具），就把 VRCC 指向那个转发工具的端口。
- **静音同步没有任何反应**：它需要 VRChat 在*同一台电脑*上运行（localhost 的 mDNS/OSCQuery 发现）、游戏里启用了 OSC，以及一个会上报 `MuteSelf` 的 avatar。
- **VRCC 启动时出现一个小窗口**：它会说明 VRCC 正在加载什么，等 VRCC 有东西可以显示了就会关闭。更新之后或重启之后的第一次启动会慢一些，因为 Windows 是第一次从磁盘上读取这个程序的文件。如果某次启动挂掉了，最新的日志文件会显示它走到了哪一步，报告问题时用得上。
- **第一次转写很慢**：启动画面关闭之后，模型加载和预热还在窗口里继续进行；之后字幕就会以全速出现。
- **报告故障**：请附上上面那个日志文件夹里最新的文件。每次运行都会写一个记录完整调试细节的文件，并保留最新的五个，所以时间戳最新的那个就是出问题的那一次。
- **再次启动 VRCC 没有反应**：同一时间只会运行一份，再启动一次只是请求正在运行的那一份把自己显示出来。如果它没有跑到前面来，可能是 Windows 把焦点留给了你最后点过的东西，这时候去任务栏按钮那里找。
- **设置步骤不再出现**：关掉面板只会让它在当次会话里消失，下次启动它还会打开，除非它要求的那些行都已经通过了。面板上的**不再显示**按钮可以把它永久关掉。不管是哪种情况，打开**设置 → 简易**，用**重新显示设置步骤**都能把它找回来。
